# 项目更新历史

本文按 `main` 分支的实际提交顺序记录项目如何从早期 RGB-D/机器人资料，逐步收敛到当前的奥比中光 Gemini 330 系列四相机车辆模板配准与喷涂路径迁移主线。历史提交中的 335L 是仿真基线型号，不代表最终采购型号。提交标题保留原文，后面的“意义”说明该次更新解决的问题。

## 当前主线

截至 2026-09-30，推荐验证链路为：

```text
4 台 Gemini 336L 固定相机（335L 为备选；仿真仍用 335L 参数）
  -> 顺序触发采集
  -> ChArUco 外参标定
  -> RGB-D 融合与 TSDF 对照
  -> 车辆模板粗配准和 ICP 精配准
  -> 将模板喷涂 TCP 路径迁移到现场车辆坐标
```

当前默认是四相机；六相机和八相机代码只用于覆盖率、标定和历史方案对照。336L 是正式硬件首选，335L 参数和相机模型继续作为软件仿真基线，实际采购仍需做同工位样机验证，详见 [`docs/project/CAMERA_SELECTION.md`](../project/CAMERA_SELECTION.md)。

## 更新阶段和决策

### 阶段一：资料和基线（1–13）

先把 D435i、真实转台、ROS 2、家具喷涂和参考代码放入同一仓库。这个阶段的目的不是形成单一产品，而是建立可比较的实验基线和硬件约束。

### 阶段二：从重建转向模板匹配（14–21）

先解决多相机结果路径和网页展示问题，再加入 Prius 模板、ChArUco 和 ICP/RANSAC 配准。核心变化是：系统不再只追求“重建一个新 Mesh”，而是使用已保存的车辆模型定位现场车辆。

### 阶段三：收敛到四相机业务链路（22–32）

四相机成为默认方案，六相机和八相机保留为对照。随后统一配准、指标和网页视图，并补齐喷涂 TCP 路径迁移与新电脑复现文档。当前工程目标是验证“现场融合点云 → 模板位姿 → 喷涂路径迁移”。

### 阶段四：重新评估 330 系列硬件型号（当前）

早期按“同步拍照、精细三维建模”理解 335L 的同步闪光灯线接口。现在的目标已明确为静止车辆的模板定位和喷涂路径迁移，多台主动红外相机更适合顺序触发以降低互扰。根据正式 Gemini 330 V1.6 规格书，最终将 336L 定为首选，335L 保留为仿真基线和备选；336L 的主动红外增强、L 型号工作距离/精度和 IP65 防护更符合车辆固定阵列。规格书未列出 338L，旧文档中的 338L 候选表述已删除。

## 后续更新规则

后续提交按以下顺序追加：

1. 先在对应子项目中修改源码和参数。
2. 运行最小回归，保存报告和可复现命令。
3. 更新子项目 README，说明输入、输出和已知限制。
4. 在根目录 README 的“更新顺序与意义”追加一行。
5. 若改变主线方案，再同步更新本文件的“当前主线”和阶段说明。
