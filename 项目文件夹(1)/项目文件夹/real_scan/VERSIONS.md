# 椅子扫描 pipeline 版本演进

## V1 — 基础管线（标定→采集→融合→Poisson）
- **方法**：RANSAC 平面拟合标定 → 转台采集 72 帧（5°步进）→ 直接融合所有深度点 → Poisson 重建
- **参数**：shift=0, 1.5mm 体素, Z_MIN=-0.10, Z_MAX=-0.001
- **结果**：模型完全看不出椅子形状，无有效分割

## V2 — 加椅子物理约束
- **改动**：增加 CHAIR_RADIUS=0.035、Z_MIN=0.003（只保留盘面上方3mm以上的点）
- **结果**：无改善，盘面噪声和椅子无法分离

## V3 — 逐像素深度差分 + TSDF
- **方法**：对每帧拟合转台平面，保留"比平面近 5mm 以上"的像素作为椅子点，TSDF 体素融合
- **参数**：DEPTH_DIFF_THRESH=0.005（5mm）, MAX_DEPTH=0.70
- **结果**：无改善，D435i 深度噪声远超 5mm，差分法失效

## V4 — 空背景减除 + Visual Hull 空间雕刻
- **方法**：先拍空转台做背景 → 放椅子后逐帧减除背景 → Visual Hull 雕刻 3D 体素
- **参数**：1.5mm 体素, VOL_X=VOL_Y=0.035
- **结果**：无改善，背景减除受光照变化影响大，Visual Hull 需要精确轮廓

## V5 — COLMAP 多视图重建
- **方法**：用 V4 采集的彩色图跑 COLMAP SfM/MVS
- **结果**：依赖外部工具，效果不理想（未继续深入）

## V6 — disparity shift + 颜色分割 + DBSCAN（当前版本）
- **核心思路**：D435i 立体匹配在均匀表面（木头、白墙）产生随机深度，不能依赖深度做精细分割；改用颜色区分椅子（浅木色）和背景

### V6 迭代过程

| 迭代 | 方法 | 结果 | 失败原因 |
|------|------|------|----------|
| **V6a** shift=150 + 深度差分 | 调 disparity shift=150 缩短最近距离，深度中值±15cm 过滤 | depth 被压缩 18.75×（45cm→2.4cm），valid 仅 2k/76.8K | shift=150 完全不可用 |
| **V6b** shift=0 + 颜色分割 + 全盘面 | 全局灰度阈值>140 + above_plate 深度过滤 + Z 验证 | 2.4M 点，DBSCAN OOM 被 kernel kill | 白墙也亮，颜色无法区分椅子/墙 |
| **V6c** VOL_Z_MIN 修正 | Z 轴方向搞反（chair world_Z<0），改 VOL_Z_MIN=-0.12 | 有模型但看不出椅子 | 白墙点也被加入 |
| **V6d** 去深度预过滤 | 移除 above_plate 深度过滤（白墙深度随机被误判为"盘面上方"）| 仍然 2.4M 点 | 白墙被颜色选中 |
| **V6e** 局部自适应亮度 + 40px 小窗 | 只搜盘心 40px 半径内，窗内局部中值+6% 做阈值，CLOSE 不做 OPEN | **1/72 帧有效，261 点**，DBSCAN 找不到簇 | 搜索窗太小/太固定，71 帧 mask<15 |

### V6 根本问题
1. **纸板不是纯暗色**：有绿色条纹+白色印刷，亮度和椅子接近，"亮像素=椅子"假设错误
2. **逐帧过滤太激进**：形态学 CLOSE + 连通域 + Z 验证层层筛选，稍有噪声就整帧丢弃
3. **固定小窗口**：椅子可能偏离盘心，40px 窗口无法适应

### V6 当前状态
- 采集数据：shift=0 的 72 帧 depth/color（质量好，盘面深度中值 ~0.42m）
- 标定数据：output/v6/calibrate.json
- 最新运行：有效帧 1/72，261 点，DBSCAN 失败

## V7 — 深度几何分离（圆柱 + Z 高度过滤）

- **核心思路**：放弃逐帧颜色分割，每帧提取盘面区域全部深度点 → 72 帧累积 → 世界坐标 → 去旋转 → Z 高度 + 圆柱 R 过滤分离椅子
- **改动**：
  - 扩大搜索范围：40px → 138px（整个盘面）
  - 深度预过滤：[0.38, 0.48]m 排除背景墙
  - 去旋转时平移到转轴中心
  - 自适应 Z 方向检测 → 强制椅子方向=盘面上方（Z>0）
  - 自适应椅子 XY 中心定位
  - DBSCAN 选离盘面最远簇
- **参数**：CHAIR_RADIUS=3.5cm, Z_PLATE_GAP=5mm, Z_CHAIR_MAX=10cm

### V7 关键发现

| 指标 | 数值 |
|------|------|
| 有效帧 | 72/72 |
| 累积点 | 260 万 |
| Z+R 过滤后 | 18K |
| DBSCAN 椅子簇 | 4.7K 点 |
| Poisson 重建 Y 高度 | 1.1cm（预期 8.8cm）|

**致命发现**：将深度 Z>1cm（"盘面上方"）的点标记到彩色图上，红点全部落在纸板上，椅子表面完全没有有效深度点。**D435i 立体匹配在光滑木面上彻底失效**，深度通道对椅子几乎不可见。

### V7 结论
纯深度几何方案在传感器层面就走不通。必须引入颜色/语义信息（YOLO/SAM）先找出椅子像素，深度只负责 2D→3D 投影。

## AI 语义分割方案测试 (2026-07-29)

### 方向一：YOLOv8n-seg — ✅ 完美

| 指标 | 结果 |
|------|------|
| 检出率 | 9/9 (100%) |
| 置信度 | 0.84 ~ 0.95 |
| Mask 质量 | 覆盖全部椅子部件（腿+座面+栅格），不侵入纸板 |
| 轮廓贴合 | 精准贴合椅子边界 |
| 模型大小 | 6.7MB (nano) |
| CPU 推理 | 单帧 ~0.3s |

**结论**：YOLOv8n-seg 是最优方案。COCO 预训练模型对"俯拍小椅子"的 domain gap 不是问题。

### 方向二：SAM 2 — ❌ 不适合

- 需要首帧人工 prompt，不适合 72 帧自动化流程
- CPU 推理速度慢，tiny 模型单帧数秒
- YOLO 已满足需求，SAM 2 边际收益小

### 方向三：圆柱几何（V7）— ❌ 已达极限

- D435i 在光滑木面深度失效是传感器硬件限制，不是算法问题
- 圆柱 + Z 过滤可以排除背景墙，但无法区分椅子 vs 纸板
- 见 V7 详细记录

### 方向四：Depth Anything V2 — ❌ 不适合（V10 验证）

- **V10 测试结果**：X=22.8cm, Y=5.9cm, Z=21.4cm——比 V9 还差
- **根本原因**：Depth Anything V2 输入 320×240 图像，椅子只占 ~6.5% 像素（~5000px），8cm 的深度变化在 AI 眼中是噪声级别。训练数据以日常场景为主，对小物体俯拍完全无法分辨内部 3D 结构
- 换用 plane geometry 约束缩放、逐像素物理裁剪均无法挽救——AI 深度输出本身就没有椅子内部结构信息

## V10 — YOLO + Depth Anything V2 稠密深度 ❌

- **核心思路**：YOLO mask 内用 Depth Anything V2 预测稠密深度替代 D435i 深度，纸板平面几何约束做度量缩放
- **参数**：Depth-Anything-V2-Small-hf (24.8M), RANSAC 平面缩放, 逐像素物理裁剪
- **代码**：`scan_recon_v10.py`
- **输出**：output/v10/chair.obj

### V10 结果

| 指标 | 数值 | 预期 |
|------|------|------|
| YOLO 检出 | 68/72 (94%) | — |
| 累积点 | 346K | — |
| 缩放失败 | 0/72 | — |
| **Y (高度)** | **5.9cm** | **8.8cm** |
| X (宽度) | 22.8cm | 4.6cm |
| Z (深度) | 21.4cm | 4.0cm |

### V10 失败原因

1. **AI 深度分辨率不足**：Depth Anything V2 在 320×240 图像中，椅子仅占 ~5000px (6.5%)，8cm 的深度变化在 AI 输出中是噪声级别
2. **平面缩放病态**：纸板是单个平面，所有参考点深度相近，仿射变换 `(a, b)` 拟合不可靠
3. **线性外推爆炸**：chair 像素的 d_rel 与纸板像素范围不同，负斜率 `a≈-0.04` 外推产生近零/负深度 → 3D 投影发散
4. **逐像素裁剪无效**：裁剪 `[d_plane-0.15, d_plane-0.001]` 迫使所有点贴近平面上方，AI 的深度变化被裁掉，退化为平板

**结论**：单目深度估计不适合小物体精细 3D 重建——输入分辨率 / 感受野 / 训练数据尺度都不匹配。

## V15 — 修复旋转中心 + 深度数据优化 (2026-08-03)

- **核心改动**：
  - 旋转中心改用数据驱动 (median of centroids)
  - 深度双边滤波 + mask 腐蚀 2px + MAD 自适应容差
  - 1mm 体素 + Poisson depth=8
  - Frame 000 跳过 SAM (抠到显示器)，使用 YOLO mask
- **代码**：`scan_recon_v15.py`
- **6 轮算法迭代**：ICP → PoseGraph+TSDF → FPFH+RANSAC → 4-view deterministic → 全72帧融合
- **结果**：所有版本 mesh 均被评估为"碎片化、有机形态、不像椅子"
- **根因诊断**：
  - 相机 46cm → D435i 深度噪声 ±2-5mm vs 椅子腿 5mm 粗 → 信噪比 ≈1
  - 标定和扫描分开 → 相机移动 → 旋转轴参数无效
  - 椅子光滑木材 → 无几何纹理用于配准

## V17 — Open3D RGBD 里程计管线（基于开源项目  2026-08-03 完成）

- **来源**：[ridanlukita/3D-scan-and-reconstruction-realsense-d435i](https://github.com/ridanlukita/3D-scan-and-reconstruction-realsense-d435i)
- **核心差异**（vs V14-V16 标定轴方案）：
  1. **不标定转台** — 用 RGBD 里程计自动追踪帧间运动（颜色+深度联合匹配）
  2. **Advanced Mode 完整 JSON 预设** — 调优所有立体匹配参数，非仅 visual_preset
  3. **激光功率 360** — 远高于我们的 150，增强光滑表面深度
  4. **Disparity Shift 动态优化** — 根据距离计算最佳视差范围，优化近距深度
  5. **TSDF 体素融合** — 对噪声更鲁棒，非 Poisson 表面重建
  6. **848×480 分辨率** — 更宽视野，更多深度点
- **录制**：`d435i_recon/v17_record.py` — 步进转台适配版（原项目为连续旋转录制）
- **重建**：`d435i_recon/v17_recon.py` — make_fragments → register → refine → integrate
- **配置**：`d435i_recon/config-custom.json`（voxel=3mm, max_depth=60cm, tsdf_cubic_size=3m, depth_scale=10000）
- **预设**：`d435i_recon/MediumDensityPreset-custom.json`

| **形状** | **完全不像椅子** |

### 失败根因

**该管线假设立场不一致**：开源项目设计场景是「相机绕静态场景移动」，RGBD 里程计直接追踪相机帧间运动。我们的场景是「相机不动 + 转台旋转」，帧间变化包含两部分：

1. **椅子像素**：绕转轴旋转（刚性变换，里程计可追踪）
2. **背景/转台面像素**：静止不动（非刚性变化，破坏里程计假设）

前景和背景的运动模式矛盾 → RGBD 里程计位姿估算全乱 → TSDF 融合将整块转台面+背景都融合进去 → 41cm 宽的 blob。

**结论**：转台扫描必须先做语义分割（mask 隔离物体），再基于转台角度算位姿，不能依赖 generic RGBD 里程计。

## 总结：17 次尝试的核心教训

| 路线 | 版本 | 失败原因 |
|------|------|----------|
| 纯深度几何 | V1-V7 | D435i 深度噪声 ±2-4mm > 椅子特征 5mm，光滑木面深度空洞 |
| YOLO mask + 深度投影 | V8 | mask 内深度点有效，但投影不准导致 blob |
| **YOLO Visual Hull** | **V9** | **最接近成功** — 高度 8.2cm (93%)，完全不依赖深度 |
| AI 深度估计 | V10 | 单目 AI 对小物体无法分辨内部 3D 结构 |
| COLMAP | V11 | 依赖外部工具，未充分测试 |
| AI 3D 生成 | V12-V13 | AI 不知道真实物理尺度/结构（竖条数不对） |
| 标定轴 + 深度 | V14-V16 | 标定→扫描位移误差 + mask 质量问题 + 深度噪声 |
| RGBD 里程计 | V17 | 假设立场不一致（相机动 vs 转台动） |

**唯一不依赖深度的路线是 V9 Visual Hull**，但要提升精度需要多仰角拍摄 + 更紧的 mask 边界。

## V18 — YOLO mask + turntable_set_v2 标定轴 + TSDF 融合 (2026-08-03)

- **核心思路**：turntable_set_v2.py 标定旋转轴 → YOLO chair mask 逐帧抠图 → 按标定轴计算每帧相机位姿 → TSDF 体素融合
- **关键改进** (vs V14-V16)：
  1. 旋转轴用 turntable_set_v2 的 `n_axis` + `center_3d`（RANSAC 平面法向 + 射线-平面交点）
  2. 深度有效率过滤（<20% 的帧丢弃）
  3. TSDF 融合对噪声比 Poisson 更鲁棒
  4. 相机→世界变换：对齐旋转轴到世界 Y + 每帧绕 Y 旋转 -θ
- **代码**：`d435i_recon/v18_recon.py`
- **配置**：voxel=5.9mm, sdf_trunc=0.04, depth_scale=10000

### 结果

| 指标 | 数值 |
|------|------|
| YOLO 检出（classes=chair） | 60/72 帧深度有效率 ≥20% |
| TSDF 融合 | 60/60 帧 |
| 顶点 | 1812 |
| 面片 | 2570 |
| 重建尺寸 | 15.1×20.9×16.4 cm |
| 预期尺寸 | 8.8×4.3×3.7 cm |
| **形状** | **不像椅子** |

### 失败根因

1. **D435i 深度在光滑木面上覆盖率极低**（3-63%）— 这是 V7 就确认的硬件限制
2. **YOLO mask 不能过滤深度空洞** — mask 内的椅子像素大部分没有有效深度
3. **TSDF 需要稠密深度** — 稀疏深度 → 大量空白体素 → 无法形成椅子形状
4. **标定轴精度有限** — turntable_set_v2 标定的是转台面圆心，不是椅子旋转中心

### 诊断工具

| 工具 | 用途 |
|------|------|
| `v18_live_depth.py` | 实时 YOLO mask + 深度热力图，观察深度空洞 |
| `v18_diag_depth.py` | 交互式逐帧诊断（← → 浏览，SPACE 播放） |

**结论**：深度传感器路线在硬件层面就走不通。D435i 立体匹配无法在光滑木面产生有效深度，任何基于深度的重建方案都受限于 3-63% 的覆盖率。

## V19 — 3D Gaussian Splatting (Colab T4, 2026-08-04)

- **核心思路**：用转台标定生成精确相机位姿（跳过 COLMAP SfM），原图直接训练 3DGS → 提取 mesh
- **数据**：V12 采集的 72 帧 500×500 RGB，turntable_set_v2 标定位姿
- **代码**：`prep_for_3dgs.py`（本地准备 zip），`output/3dgs/colab_3dgs.py`（Colab notebook）
- **训练**：T4 GPU, 30000 轮, train PSNR 34.3, test PSNR 22.2

### 结果

| 指标 | 数值 |
|------|------|
| 高斯球数量 | 94137 |
| 过滤后（距原点<8cm）| 9319 |
| Poisson mesh | 不像椅子 |
| **形状** | **不可辨认** |

### 失败根因

1. **椅子太小（~100px / 500²）** — 3DGS 需要物体占据足够像素才能学到表面细节
2. **光滑木面无纹理** — 梯度优化只能依赖轮廓边缘，无法恢复表面几何
3. **标定位姿精度有限** — 旋转中心估计有误差，累积到 72 帧后物体形状发散
4. **背景干扰** — 原图中背景面积远大于椅子，大量高斯球浪费在背景上（过滤后只剩 10%）

**结论**：3DGS 与 COLMAP 本质上都依赖「足够的纹理特征」+「物体占画面足够比例」。小尺寸光滑木材不满足这两个前提。

## V20 — 原始 IR 立体匹配 + 多视角融合 ❌ (2026-08-04, 8 轮迭代)

- **核心思路**：绕过 D435i ASIC 芯片，直接读 IR 左右原始图像 → OpenCV StereoSGBM 软匹配 → 转台标定轴融合 72 帧 → Poisson mesh
- **采集**：1280×720 IR + 深度 + RGB，转台 5°×72 帧，IR 投影仪 always on + 激光功率 360
- **代码**：`capture_v20.py`, `process_v20_sgbm_hires.py`, `process_v20_fuse.py` → `_v2/v3/v4/_hires.py`

### 迭代过程

| 迭代 | 方法 | 结果 | 失败原因 |
|------|------|------|----------|
| v1 | 降采样 640×360 SGBM + 标定位姿（`p_plane=R@p_cam+t`） | 1.7m 圆环 | **变换方向写反**（应该是 `p_cam=R@p_plane+t`），Z 差 2× |
| v2 | 简化竖直轴 + 中心裁剪 | 圆柱体 | 标定轴倾斜 [-0.286,-0.860,0.422]，纯竖直轴不对 |
| v3 | 修正变换方向 + 标定轴方向 | 圆盘 | 标定 Y=317mm 不匹配椅子在画面中的实际位置（Y≈0） |
| v4 | 紧裁剪 80×60 + 深度自适应过滤 | 圆盘 | 椅子仅 34×29px，95% 点是背景 |
| search | 暴力搜索 48 组轴参数 (X/Y/方向) | 所有得分 39.9-41mm | **噪声主导**，分数对参数不敏感 |
| hires | 全分辨率 1280×720 中心裁剪 400×300 SGBM | 覆盖率 62.6% (↑ 26pp) | 深度噪声 std 28mm ≈ 椅子特征 43mm → Poisson 平滑成圆盘 |
| (最终) | 最佳参数 + hi-res + 紧裁剪 | **圆盘，不像椅子** | 噪声和椅子信号同量级，无法分离 |

### 关键数据

| 指标 | 降采样版 (640×360) | 全分辨率版 (400×300) |
|------|---------------------|------------------------|
| 椅子像素 | ~34×29 px | ~67×58 px |
| 中心覆盖率 | 90% | 87.4% |
| 全图覆盖率 | 36.1% | 62.6% |
| 深度中值 | 408mm | 415mm |
| **深度噪声 std** | **27mm** | **28mm** |
| 椅子特征尺寸 | 43×37mm | 43×37mm |
| 信噪比 | **1.6:1** | **1.5:1** |

### 根因

**SGBM 深度噪声 (28mm std) 与椅子特征尺寸 (43mm 宽, 37mm 高) 同量级。** 即使位姿完全正确，Poisson 重建也会把噪声+椅子信号一起平滑成圆盘。提升分辨率不能降低深度噪声（std 几乎不变），只能增加采样密度。

IR 立体匹配的物理极限：50mm 基线 + 400mm 距离 → 1px disparity 误差 ≈ 5mm 深度误差。木面纹理弱 → SGBM 匹配误差 3-5px → 15-28mm 深度噪声。

**结论**：IR 立体路线在 8.8cm 光滑木椅上走到头了。不是位姿问题，是深度质量不足以解析椅子结构。
